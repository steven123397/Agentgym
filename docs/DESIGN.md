# 专注任务规划器设计

## 目标与范围

在现有原生 HTML、CSS 和 ES Module 基座中实现一个无需后端的专注任务规划器。应用以本地任务为唯一数据源，提供欢迎引导、任务管理和基于 8 小时预算的今日计划，刷新页面后仍可恢复数据。

## 页面结构与交互

### 初始页面

当任务列表为空时显示欢迎页：包含产品价值主张、三个核心能力说明、8 小时专注预算的视觉摘要，以及“创建第一个任务”主按钮。按钮会切换至工作台并打开任务表单。用户删除最后一个任务后回到该引导页。

### 主工作台

有任务时显示工作台，包含：

- 顶部品牌、任务概览和“新建任务”入口。
- 视图标签：“全部任务”展示任务卡片，“今日计划”展示算法结果。
- 全部任务视图：任务卡显示优先级、预计时长、截止时间和完成状态；可切换完成、编辑、删除。
- 今日计划视图：展示已安排的顺序、总时长和剩余预算；未安排任务显示明确原因。
- 内嵌表单：创建或编辑任务时显示，支持取消。字段即时显示验证信息，不保存无效数据。

页面以单列弹性布局为小屏默认，较宽屏幕使用侧栏说明/概览与主内容并列；按钮在窄屏可自然换行，交互控件保持可点击尺寸。

## 数据模型与持久化

任务使用以下结构：

```js
{
  id: "task-...",          // 稳定唯一标识
  title: "准备周报",       // 去除首尾空格后的非空文本
  priority: "high",        // "low" | "medium" | "high"
  minutes: 60,              // 1–480 的整数分钟数
  dueAt: "2026-08-02T10:00", // datetime-local 的本地时间字符串
  completed: false,
  createdAt: 1720000000000  // 用于完全相同排序条件下的稳定排序
}
```

整个任务数组保存到 `localStorage` 键 `focus-planner.tasks.v1`。启动时解析并逐条校验数据；损坏、缺失或不符合字段约束的条目会被忽略，避免本地存储异常使页面无法使用。每次新增、编辑、删除或切换完成状态后立即覆盖保存。

## 模块职责

- `src/planner.js`：无 DOM 依赖的计划算法、任务规范化和排序辅助函数，便于 Node 测试直接导入。
- `src/main.js`：应用状态、渲染、事件委托、表单验证和 `localStorage` 读写；导入计划算法渲染今日计划。
- `src/style.css`：欢迎页、工作台、表单、卡片、计划状态及响应式样式。
- `tests/planner.test.js`：验证计划算法的排序、预算、完成状态与未安排原因。

## 今日计划生成算法

1. 读取全部任务，先排除已完成任务。
2. 将剩余任务按优先级 `high → medium → low`、截止时间从早到晚、创建时间从早到晚、ID 字典序排序。无效/缺失截止时间排在具有有效截止时间的同优先级任务之后。
3. 依序检查每项任务：若 `minutes` 不大于当前剩余预算（初始为 480），放入 `scheduled` 并扣减时长；否则放入 `unscheduled`，原因是“剩余 X 分钟，不足以完整安排此任务（需 Y 分钟）”。
4. 返回 `scheduled`、`unscheduled`、`totalMinutes` 与 `remainingMinutes`。算法不依赖当前时间，因此相同输入总产生相同输出。

由于先排序、后逐项装入，优先级和截止时间的顺序始终可解释；为遵守“不完整执行不安排”，不会跳过更靠前的任务后再回填低优先级任务。

## 关键边界情况

- 任务标题仅包含空白或时长不是 1–480 的整数：阻止提交并提示。
- 截止时间是必填项，无法解析的值不会由表单写入；旧的异常存储项会在读取时丢弃。
- 完成任务在全部任务中保留但视觉弱化，且绝不出现在今日计划。
- 单项任务恰好填满预算时可以安排；超过当前预算时不拆分，并显示余量与所需时间。
- 无可计划任务时，今日计划明确说明是任务均已完成或尚无任务。
- 删除最后一个任务时进入欢迎页；删除和编辑先通过原生确认/可见表单避免误操作。
- `localStorage` 不可用或写入失败时页面继续在内存中工作，并显示非阻断提示。

## 测试与验证

- 运行 `npm test`，保留基座挂载点和入口加载测试。
- 使用 Node 测试对纯计划模块覆盖：优先级与截止时间排序、480 分钟上限、恰好填满预算、无法完整执行的原因、已完成任务排除和稳定的同值排序。
- 执行 `npm run dev`，请求入口页面确认开发服务可启动；在浏览器中手动检查欢迎页、创建、编辑、完成、删除、视图切换和刷新后持久化。

## 主要取舍

不引入框架或组件库，以一个小型状态对象、模板渲染和事件委托保持基座简单。任务表单放在工作台内而非增加路由或模态基础设施，减少状态与可访问性复杂度。计划算法以纯模块导出，优先保证规则清晰、确定和可测试，而不追求更复杂的背包优化。
